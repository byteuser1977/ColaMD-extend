## v2.7.13 · Slide Layouts

Slide layouts. Each page declares its layout and page copy with one header block after `---` (`<!-- slide: cover` on the first line, then `kicker / label / chapter`); eleven layouts ship built in (cover, section, agenda, KPI cards, timeline, steps, card matrix, two-column, figure, quote, closing, after dsh-ppt's role taxonomy), and pages without a layout fall back to a denser article style. The first heading is the page title, the first paragraph after it becomes the lead, and a paragraph just before it is the kicker fallback; covers use an h1 title plus an h2 subtitle. A page can fine-tune with `<!-- slide-css -->` or attach a `<!-- slide-js -->` presentation script (it runs in a sandboxed iframe that cannot touch the editor; PDF export never executes it). The deck is redrawn in a magazine style: full-bleed 16:9 pages, a PPT-sized heading scale, serif headings with monospace chrome, and hairlines instead of color blocks. One `<!-- deck … -->` block at the top configures logo, brand, title and date; chrome stays on covers and section pages and fades only on the closing page, and the logo accepts paths relative to the document. Layout colors read theme variables only, so switching themes reskins every layout; `.cm-md-slide-*`, `.cm-md-page-title` and `.cm-md-page-lead` are a public contract, and the `--slide-*` design tokens let an imported theme CSS define slide titles, sizes and chrome character directly; `resources/templates/slides.md` is the standard template and `resources/demo/slides-demo.md` shows one page per layout.

Also fixed an old presentation bug: in longer documents, advancing past a middle page would silently stop working — the page count was taken from the slice CodeMirror had actually rendered, and pages outside the viewport were never counted. The slideshow now renders the whole document before counting pages, so decks of any length play from start to finish.
