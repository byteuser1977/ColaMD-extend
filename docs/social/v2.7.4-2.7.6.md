# ColaMD 假期三版综合文案（v2.7.4 – v2.7.6）

用途：假期连着发了三版（北京时间 10 月 6 日深夜、10 月 7 日上午、10 月 8 日上午），都是修细节、没有新功能。这篇是给没跟上节奏的人一次看全的版本，可以直接发社区。单版本原文在 `docs/social/v2.7.3.md`、`v2.7.4.md`、`v2.7.5.md`、`v2.7.6.md`。

## Chinese（长版）

假期这几天，ColaMD 连着发了三个版本：2.7.4、2.7.5、2.7.6。都是修问题，没有新功能，也没有界面大改。没顾上更新的，这一篇就够了。

**一、排版不再跟着光标动。** 以前光标停在哪一行，那一行的 `**`、`#`、`[]()` 就会冒出来等你改，屏幕上的样子一直在变。现在渲染模式下每一行都是干净排版，要改标记本身就去源码模式（视图菜单里的「源码模式」，快捷键 `⌘/`），它照样能编辑，点哪儿写哪儿。屏幕上是排版、文件里是原文，这两件事一直同步。

**二、文件（大纲）列表打开时，正文让开。** 面板是浮在窗口上的一列。从 2.7.3 起正文忘了给它让位，面板一开就盖住一截，面板越宽盖得越多，滚动条也藏在面板底下。现在正文按面板所在的那一侧让开，并且在剩下的可见区域里居中，面板放左边、放右边都对；切到源码模式时文字也不会横向跳。

**三、复制和导出里的两个老毛病。**

- 复制的 HTML 里，每个空行都会被翻成一个空段落，粘到 Typora 或者其他编辑器里，段落之间凭空多一整行。现在空行只是段落分隔。导出 HTML 走的是同一段代码，一起修好了。
- 深色主题里选中文字几乎看不见。选中色带一直是编辑器内核自带的一套默认色，跟主题无关。现在跟随主题，各套主题的对比度都回到能正常阅读的范围。

**四、几个「明明按了却没反应」的地方。**

- 查找的「下一个」以前计数在走、界面不动，现在真的会跳过去。
- 有序列表删掉中间一项，序号会自己接上。关键是改在**文件本身**，不是只在屏幕上好看：复制出去、用别的软件打开、纯文本导出，序号都对，撤销一步能回到改之前。打开文件、Agent 改写文件这些不是你动手的场合，序号一律不动。
- 下载的主题现在真的生效了。之前导入一套主题只换了底色，加粗、标题、引用块的颜色纹丝不动，因为主题文件里写的还是旧编辑器内核的选择器。现在全部改正，并且加了一条验收：主题里任何一条规则只要匹配不到真实元素，发版就会失败。
- 导出的 HTML 与 PDF 不再丢掉列表起点（以 `5.` 开头的列表以前会从 1 数起）。

**五、`⌘+` / `⌘-` 只放大文字，不再缩放整个界面。** 以前它缩的是整页，顶栏跟着一起变高，而 macOS 的红绿灯是系统按窗口画的、尺寸不跟着变，所以放大之后就不居中了。现在界面尺寸一动不动，只有文档跟着变大变小，和设置里的字号是同一个值。顺带修了一个只调字号会把主题字体顶掉的问题；`⌘0` 恢复默认字号，你自己挑过的字体不会被清掉。

除此之外还有两个小的：自定义主题有了一份带注释的模板（`themes/template.css`），变量和选择器都可以照着抄；仓库里那个一直没人维护的 VS Code 小扩展撤掉了。

**怎么升级：** 菜单里「检查更新」直接升，或者去 Release 页面下载。已经写好的文件一个字节都不用动，升级上来直接能读。

谢谢这几天报告问题的几位，上面每一条都是从具体的一次使用里找出来的。

## English（long version）

Over the holiday ColaMD shipped three releases: 2.7.4, 2.7.5 and 2.7.6. All three fix things, none adds a feature or redesigns anything. If you did not keep up, this is the whole story.

**1. Typography no longer moves with the caret.** The line your caret sat on used to reveal its own `**`, `#` and `[]()` so you could edit them, which meant the page kept changing shape while you worked. Now every line in the rendered view is clean typography, and markup itself is edited in source mode (View -> Source Mode, `Cmd+/`). The rendered view stays editable: click where you want to type. What you see and what is in the file stay in sync.

**2. With the file (or outline) panel open, the text steps aside.** The panel is a column that floats over the window. Since 2.7.3 the text had stopped making room for it, so opening the panel covered the end of every line, wider panels covered more, and the scrollbar hid behind it. The text now steps aside on whichever side the panel sits and stays centred in what is left, docked left or right, and switching to source mode no longer shifts it sideways.

**3. Two old problems in copy and export.**

- Every blank line in the copied HTML was rendered as an empty paragraph, so pasting into Typora produced an extra blank line between paragraphs. A blank line is now just a paragraph break. The HTML export shares that code, so its version is fixed too.
- Selected text in dark themes was almost unreadable: the selection band came from the editor core's own defaults, unrelated to the theme. It now follows the theme, and contrast is back in the readable range on every theme.

**4. A few places where pressing the thing did nothing.**

- Find Next used to advance its counter without moving the view. It scrolls now.
- Deleting an item in the middle of an ordered list renumbers the rest. What matters is that the file itself is rewritten, not just the screen: copy it out, open it elsewhere, export as plain text, the numbers are right, and one undo takes it back. Opening a file or an agent rewriting one never touches the numbers.
- Downloaded themes now actually work. Importing one used to change only the background while bold, headings and blockquotes stayed put, because the theme files still carried the old editor core's selectors. They are fixed, and a release now fails if a theme rule matches nothing in the real editor.
- The HTML and PDF exports no longer lose a list's starting number (a list starting at `5.` used to be numbered from 1).

**5. `Cmd+` / `Cmd-` change only the text size.** They used to zoom the whole window, chrome included, while macOS draws the traffic lights itself at a fixed size, so they ended up off centre. Interface sizes no longer move; only the document grows and shrinks, sharing one value with the font size in settings. The same change fixes a problem where changing only the size pushed the theme's font aside; `Cmd0` restores the default size and keeps a font you picked.

Two smaller things: custom themes come with a commented template (`themes/template.css`) to copy from, and the unmaintained VS Code helper extension is gone.

**How to update:** Check for Updates in the menu, or download from the Releases page. None of your files need to change: open them as they are.

Thanks to everyone who reported something over the holiday. Every item above came out of a real session with the app.
